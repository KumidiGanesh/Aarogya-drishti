# Oral image research pipeline (not clinical)

This isolated toolkit has no model weights and no patient data. It does not train or infer. The manifest validator checks de-identification fields, consent/annotation provenance, and patient-level split leakage. `evaluate.js` computes metrics only from supplied labels and predictions, and refuses to write over an existing report. A report is research evidence, not proof of clinical validation.

## Dataset contract

Use opaque `item_id`, HMAC-derived `subject_key` (never a patient ID), and `encrypted_object_id` that resolves only through an access-controlled service to the existing encrypted image store. Keep the identity/HMAC key outside the dataset. Every record requires `consent_record_id`, `consent_granted: true`, `annotation_status: expert_reviewed`, and an opaque `reviewer_key`. Consent must explicitly cover research model development; existing care/AI-processing consent is not research consent. Do not export images to this toolkit. Dataset versions are sealed with a SHA-256 digest over canonical schema-versioned manifest JSON; the API verifies the digest before returning items and rejects tampered sealed manifests. The API accepts explicit split assignments and enforces a single split per participant; it does not claim a deterministic automatic split algorithm. Assign train/validation/test by subject before preprocessing, and keep test labels inaccessible during development.

For the API curation service, configure `RESEARCH_SUBJECT_HMAC_KEY` as a secret of at least 32 characters. Research APIs remain unavailable unless `RESEARCH_GOVERNANCE_ENABLED=true` and the institution has configured its genuine approval reference, governance body, contact, and approved retention/withdrawal policy. The application cannot verify the approval itself; never fabricate the settings. A participant must grant the versioned consent at `/patient/research-consent`; legacy clinical or general consent records are not sufficient. Add an existing uploaded image using `POST /api/research/datasets/:id/items` and that participant's current `research_consents` record; annotate it through the reviewer endpoint, then seal only after all consent remains active and all three splits are populated. Withdrawal blocks further use in these APIs and does not delete clinical records or recall prior exports/results.

## Evaluation

Predictions JSON must be a manifest array with the listed provenance fields plus binary `label`, measured `probability`, `split`, `independent_test: true` on test rows, and optional non-identifying subgroup values. Metadata JSON requires `independent_test: true`, `dataset_version`, and `model_version`. Run `node research/oral-cv/validate-manifest.js <manifest.json>` then `node research/oral-cv/evaluate.js <predictions.json> <metadata.json> <new-report.json>`. No report is produced for empty/malformed evaluation data. AUROC is null when the test set lacks either class. Calibration includes Brier score and 10-bin ECE.

Training requires a separately approved, consented dataset, reproducible preprocessing/training code, independent patient-level test set, model card, security review, and clinical validation evidence. Do not use Gemini preliminary observations as ground truth.

After a training run produces a real model file, record its SHA-256 identity without overwriting earlier records: `node research/oral-cv/record-experiment.js <run-metadata.json> <actual-model-artifact> <new-record.json>`. Metadata must include experiment id, dataset version, code revision, integer seed, and `patient_level_split: true`. The script does not train a model or create weights.
